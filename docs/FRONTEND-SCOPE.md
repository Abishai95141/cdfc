# docs/FRONTEND-SCOPE.md — everything the frontend must contain

**Written 16 August 2026. BUILT 16 August 2026** — every screen below is server-rendered in
`src/cdfc/surface/web/` and asserted in `tests/surface/test_web_screens.py`. The §1 status column
records what shipped; the rules and component contracts are unchanged and are what the tests check.

## THE CSP DECISION, taken 16 August 2026

§10.7 required `default-src 'none'` with **no `script-src`**, which is what makes *"no script
reached this page"* enforceable rather than a claim. A real interactive product needs a script. The
resolution is **per-route policy**, and it is a narrowing rather than a loosening:

| routes | policy |
|---|---|
| `/v1/runs/{id}/report.html` and all of `/v1/*` | `default-src 'none'`, **no `script-src` at all** |
| the twelve screens | `default-src 'none'; script-src 'self'` — one same-origin file, no `unsafe-inline`, no `unsafe-eval`, no host in any directive |

The old header was applied to every response *because every response was static*, and a blanket
header says nothing about what is IN any of them.
`test_web__the_report_route_forbids_script_in_the_header_AND_in_the_bytes` now checks the policy on
the attested artifact **and** greps its served bytes for `<script`, which the blanket header never
did. `test_web__csp_is_chosen_by_prefix_so_a_new_api_route_cannot_get_the_looser_one` walks both
route tables rather than sampling two paths.

**Server-rendered, and the script is an enhancement.** Every count, row, reason and fraction is in
the HTML before any script runs, and every screen — including all three POST flows — works with
scripting off. The script adds drag-and-drop with real upload progress, copy buttons on digests, a
hover readout on the history chart, and a busy state on submit. It adds no data and computes no
fraction.

## §0 — The five rules that constrain every screen

These are not style guidance. Each is enforced somewhere in the backend, each has a negative
control that has been observed red, and **a screen that violates one is a screen that must not
ship.** They are listed first because they decide the shape of every component below.

| # | Rule | Why | Enforced by |
|---|---|---|---|
| **R1** | **No green tick, no all-clear.** No `✓`, no checkmark glyph, no green fill on a status, no word in `BANNED_PHRASES` ("all clear", "operational", "compliant", "passed") | The product's claim is *what was not checked*. One tick undoes it | `ci/no-green-tick.sh`, gate rows 1 · SG1 |
| **R2** | **No bare rate.** Every percentage renders with both integers of its fraction, on the same line | A percentage carries no evidence of its own arithmetic. v0 printed `18.09%` over a denominator nobody could reconstruct | `ci/no-bare-rate.sh`, row 4 |
| **R3** | **No settled count without its admission state**, in the same block — within 2 DOM ancestors, not merely the same page | `PRE-GATE` says the instrument is unqualified. A count that travels without it reads as a verdict | NC-A05, SG3 |
| **R4** | **No total row on any cross-template view.** Counts aggregate; fractions do not | *"Our clients average 87% settled"* divides one workbook's unlocked-cell mask by another's | `test_api__portfolio_has_no_total_row`, row 119 |
| **R5** | **Absent ≠ empty ≠ zero.** Three distinct renderings, and the "not measured" one carries **no digit at all** | A blank where a count should be reads as *nothing to report*, and a reader cannot tell it from a genuine zero | NC-A14, NC-D03 |

**The colour system already encodes R1.** `src/cdfc/surface/design.py` has no green in the palette,
and `test_style__no_colour_falls_in_the_green_hue_band` checks the *generated bytes* — because the
fastest way to reintroduce an affirmative colour is to add it under a name nobody would grep for.
Use the tokens; do not add colours.

## §2 — S-1 · Drop screen

**Built and shipping.** Specified here so a rebuild does not lose the constraints.

### Controls — exactly one

| Control | Type | Behaviour |
|---|---|---|
| `#filing` | `input[type=file]`, `accept=".xlsx"` | The only control. Required |
| Submit | `button[type=submit]` | `POST /v1/filings`, multipart |

**There is no second control, and this is a coverage argument rather than a taste in minimalism.**
Every setting on this screen would be a way to change *what gets checked* without changing *what
the report says was checked* — a strict-mode toggle, a sheet selector, a skip-empty-rows box. Each
silently moves the denominator, and the Unchecked panel is defeated from outside the panel.
`test_drop__exactly_one_control` fails if a `select`, a checkbox or a radio appears.

### States

| State | Trigger | Render |
|---|---|---|
| idle | — | lede + control + the "no settings" note |
| uploading | submit | progress; **no percentage** unless both integers show (R2) |
| `201` | accepted | redirect to S-2 |
| `413` | over 25 MB | "that file is larger than the 25 MB cap" + the actual size |
| `415` | not a zip | "an .xlsx is a zip container; this file does not begin with `PK`" |
| `422` | `template_unbound` | **the structural fingerprint, copyable**, and a link to S-10. *A 422 that only says "unknown template" leaves an operator with nothing to act on* |

## §3 — S-2 · Run report

The self-contained `report.html` already exists and is byte-identical to what the attestation
covers. **The interactive view must never replace it** — offer both, and make the file the
canonical artifact.

### Hero — three elements, and the third is not optional

```
0 failures across 1,898 checks          <- settled count
1,849 fields were not checked           <- THE PRODUCT
predicate set: PRE-GATE · denominator: v3
```

| Element | Source | Rule |
|---|---|---|
| failures / checks | `settledFraction.settled`, `.inScope` | R2 — both integers |
| **not checked** | `settledFraction.notChecked` | Same visual weight as the first line. Never smaller, never below the fold |
| admission state | `settledFraction.admissionState` | **R3** — same block, ancestor distance ≤ 2 |
| denominator warning | `settledFraction.denominatorWarning` | Rendered in full, never truncated to "provisional" |

### The coverage band

Eight segments, from `closure`. **The band never fills** — it always ends with
`NOT_SETTLEABLE_FROM_ARTIFACT` and `RESIDUE`, hatched, at a 12‰ floor so they cannot vanish at any
width. A band that reaches 100% is a bug.

| Segment | Field | Colour token |
|---|---|---|
| settled — check ran, did not fire | `settled` | `text-primary` |
| settled — check ran and fired | `failed` | `accent-ink` |
| not settled — could not decide | `indeterminate` | `border-strong` |
| not settled — did not run | `notRun` | `border` |
| **not checked — no predicate exists** | `noPredicate` | `border` hatched |
| not settled — errored | `error` | `accent-ink` |
| not settleable from this filing | — | hatched, **12‰ floor** |
| residue | — | hatched, **12‰ floor** |

### Buttons

| Button | Action | Note |
|---|---|---|
| Download report | serve `report.html` bytes | **Never re-render.** The attestation covers the file on disk |
| Download attestation | `GET .../attestation.json` | |
| Verify this report | → S-11 | |
| Explore cells | → S-4 | |
| What wasn't checked | → S-3 | **Above the fold, not in a footer** |

## §4 — S-3 · Unchecked panel — *this is the product*

The only screen in this category that tells a reader what the tool did **not** do. It is not an
appendix and it does not live behind a tab.

### Per group

| Element | Source | Rule |
|---|---|---|
| reason code | `groups[].reasonCode` | From the closed 30-code vocabulary. **An unknown code is an error, not a row** |
| count | `groups[].count` | |
| remedy | `groups[].remedy` | **No fallback string, ever.** `MissingRemedy` raises server-side; the client must not substitute "see documentation" |

### The three residue states — R5 applied to our own panel

| State | Render | Digit? |
|---|---|---|
| `exhibits: null` | "residue not yet measured — the procedure has not been run against this predicate set" | **NO DIGIT** |
| `exhibits: []` | "the procedure ran and returned no survivors. That is not good news on its own: a residue of zero means either the check set is complete or the fault model is too narrow to construct a survivor, and the second is more likely" | yes |
| `exhibits: [...]` | *n* demonstrated survivors, each with what was changed and why nothing caught it | yes |

### `breakdownUnavailable` — a state the client MUST handle

`GET /v1/runs/{id}/unchecked` currently returns `total: 1849`, `groups: null` and a
`breakdownUnavailable` string, because `run.jsonl` records only cells that were *evaluated*.

**Render the total and the explanation. Do not render `groups: null` as an empty list** — an empty
list reads as *every unchecked cell is accounted for and none has a reason*, which is false.

## §5 — S-5 · Portfolio — the screen with the sharpest rule

The administrator's view, and **the single most dangerous screen in the product.**

### Table columns — fixed

`entity · template · runId · settled · fieldSurface · notChecked · admissionState`

### R4, in full

**No total row. No average row. No footer aggregate. No "portfolio health" number. No sparkline of
a cross-template mean.**

A summary card **may** carry counts — *how many filings, how many entities, how many templates* —
because a count of filings has a denominator anybody can state. It **may not** carry a fraction.

Sorting by `settled` is permitted. **Sorting by an implied percentage is not**, because that
percentage would have to be computed client-side over incommensurable denominators — which is R4
being violated in the sort comparator instead of in the DOM.

## §6 — S-6 · Predicate library (BLOCKED — needs a real handler)

Each row carries **all** of the following, or the row does not render:

| Element | Rule |
|---|---|
| `kr_claimed` **and** `kr_all_classes` | **Both or neither** — `UnpairedKillRate`. The GAP between them is the number a reviewer wants: G2's bar is measured over the classes a predicate *claims*, and the claim is selected after the campaign has run |
| Six integers `G · U · I · O · R · K` | Never two. `O == G − U − I` |
| `I` beside `U/G`, with the **cells named** | An integer without its cells is an apology. Every indeterminate exclusion *raises* `K/O` in the direction that flatters us |
| `instrument_label` | The literal `SAME-AUTHOR — a weaker instrument` when `ci/GATES.md` records G-EVAL as `PASSED — NOT INDEPENDENT`. **Read from the gate registry, never a constant** |
| flag-everything column | On every row. Without it a kill rate is *reach*, not quality |
| FFR cell | Three uninformative cases, all rendering **no digit** |
| severity tier | `BLOCKING` / `ADVISORY` / null |

### G-CORPUS header — three outcomes, rendered distinctly

| Outcome | Render | Digits? |
|---|---|---|
| `PASS` | `n` filings, provenance, Wilson interval | yes |
| **`RESTRICTED`** | the literal string **`G-CORPUS: RESTRICTED`**, naming which predicate classes are licensed | yes, for licensed classes only |
| `FAIL` | the corpus-provenance census | **none anywhere** |

**Today the repo is `RESTRICTED`** (`n = 40`, `TEMPLATE-COMPUTED`, `FOREIGN_ENGINE`, capped
`ADVISORY`). A restricted pass rendered as a pass is the whole failure this gate exists to prevent.

## §7 — S-8 · Attrition funnel (BLOCKED)

Stages in **gate order**: `generated → G0.scope → G1.binds → G3.proof → G2.kill → G3.empirical →
G4.ffr`.

- **Three integers per stage** — `entered / skipped / survived` — never two.
- `entered == skipped + survived + rejections` is asserted; **a skip may not be laundered into a
  survival by omission.**
- A stage where `skipped == entered` renders **`NOT APPLICABLE — 0 evaluated`**, not a full-width
  survival bar. *G0 over the 280 clause-less harvested candidates is the live instance.*
- Every rejection row shows **the number that decided it**. A rejection without its number is an
  opinion wearing a gate's name.

### The obligation-coverage pair — together or not at all

```
predicates_with_a_STATUTE_obligation:  0 / 280
predicates_with_a_TEMPLATE_obligation: 280 / 280
no harvested predicate yet implements a statutory clause
```

Publishing a zero is the honest case and **must not be special-cased into an empty state.** A
STATUTE count alone reads as *nothing is covered*; a TEMPLATE count alone reads as *everything is*.

## §8 — S-9 · History (BLOCKED)

- The series **must be able to step down.** No `running_max`, no smoothing, no clamping, no
  sorting by value.
- A decrease renders **with its cause**; a decrease without a cause does not render at all.
- **The step-downs are the most credible thing on this chart** — they are the evidence that the
  number is measured rather than accumulated. Style them as data, not as warnings.

## §9 — Cross-cutting components

| Component | Rule |
|---|---|
| `<AdmissionBadge>` | Renders `PRE-GATE` / `PARTIALLY-ADMITTED` / `ADMITTED` with the full caveat. **Must be a required prop of any component showing a settled count** — make it impossible to omit in the type system, not merely a convention |
| `<Fraction>` | Takes numerator *and* denominator. **Cannot be constructed with a percentage alone** — mirror `SettledFractionOut`'s server-side rule in the client type |
| `<Count>` | Three states per R5: number, measured-zero, not-measured. The last renders **no digit** |
| `<ReasonCode>` | Only the 30 known codes; an unknown code renders as an error, never as a label |
| Empty states | Never "All good!" or "Nothing to report." An empty list of *failures* is not an empty list of *unchecked cells* |
| Error toasts | Show the server's `detail` verbatim — the backend's messages carry the argument |

## §10 — What the frontend must NOT do

1. **Never compute a settled fraction client-side.** Two implementations is one more than the
   project can defend. Render what `/v1/runs/{id}` returns.
2. **Never aggregate across templates.** See R4.
3. **Never re-render the report.** Serve the bytes; the attestation covers them.
4. **Never add a setting to the drop screen.**
5. **Never render `null` as `0`, or an empty list as "none found".**
6. **Never introduce a colour outside `design.py`'s palette**, and never one in the green hue band
   (80–160°, sat > 0.15, lightness 0.2–0.8).
7. **No client-side analytics or external fonts/CDNs.** The served CSP is
   `default-src 'none'; style-src 'unsafe-inline'; img-src data:; form-action 'self'` — an external
   request will simply fail, loudly, which is the intent.

## §11 — What was found while building it

Five defects, and none of them was in the specification above.

1. **The report renderer had no caller.** `cdfc.surface.render.render_report` has existed since
   P14-B1 and nothing in the pipeline invoked it, so no run on disk carried a `report.html`,
   `GET /v1/runs/{id}/report.html` was a permanent 404, and *Download the report* was a control
   that could not work. A renderer with no caller passes its own unit tests and has never once run
   on a real artifact. `cdfc run` now renders it beside the run.
2. **The whole test suite had never run.** `tests/negative/test_nc_model_free.py` did
   `from negative.importgraph import …`, which pytest cannot resolve without `tests/` on the path —
   a **collection error**, which aborts the run rather than failing a test. `make verify` reached
   zero assertions. Fixed with `pythonpath = ["src", "tests"]`, which then exposed three more
   failures that had been hidden behind the abort.
3. **The funnel's stage arithmetic did not close in general** — `survived` was computed without
   subtracting `skipped`, which holds only while `skipped` is zero.
4. **A regex over OOXML** in the churn sweep. `ci/no-regex-over-xml.sh` caught it, and the pattern
   was genuinely wrong: it required `name` before `r:id` in document order.
5. **The two hatched band segments vanished at zero**, so the band could reach its own far edge —
   the one thing it must never do.

And two of the five rules went red on this file's own sibling: `ci/no-green-tick.sh` and
`ci/no-bare-rate.sh` both refused `components.py` for naming banned tokens **in a docstring
explaining the rule**. The gates were right; the prose moved.
