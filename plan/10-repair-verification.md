## §0 — A FINDING ABOUT THE APPARATUS, FOUND BEFORE ANY FINDING ABOUT THE PLAN

`plan/03-phases-verdict.md` contained **one raw NUL byte** (offset 30288, line 333, inside the code span
`` `<NUL>`-adjacent escapes ``). `file(1)` classified the document as `data`, and **GNU/BSD `grep` silently
skips binary files**: every grep over `plan/*.md` returned zero hits in `03`, including greps for ids that
`03` defines fifteen times.

This is not cosmetic. The F27 repair's enforcement artifact is
**`ci/catalogue-ids.sh` — "a grep over `plan/*.md` asserting each `NC-` id appears in exactly one document
as a *definition*"** (`01` §2, `02` R5a registry row 18). Against the tree as delivered, that gate would
have **skipped `03` entirely and reported the id space clean** — while `03` and `04` were defining seven of
the same ids. The gate written to catch F27 would have run green over the largest instance of F27 in the
repository.

**Fixed** (see §6): the raw NUL is now the literal `U+0000`. **Recommended addition to R5a:**
`ci/catalogue-ids.sh` must assert `file --mime-encoding` is `utf-8` for every scanned path, or use
`grep -a`. *A scan set that silently drops a file is the same defect as a scan set that shrinks — the plan's
own F28.*
